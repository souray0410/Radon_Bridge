1. PROJECT MISSION
================================================================================

The project develops R&B (Radon Bridge):

A general communication mechanism that allows neural representations of different intrinsic dimensionalities, modalities, architectures, depths and downstream tasks to exchange information through a common generalized Radon/projection domain.

The long-term scientific target is a Nature Biomedical Engineering-level study.

The project must nevertheless be designed so that it can be progressively expanded or safely narrowed according to:

- experimental evidence;
- available data;
- statistical strength;
- project time;
- biomedical significance.

The governing principle is:

    Build the method generally from the beginning;
    validate the scientific claims progressively.

Do NOT initially hard-code R&B for only:

- 2D–3D;
- CFP–OCT;
- eye–heart;
- one specific network;
- one specific layer;
- one specific task;
- one specific number of communication participants.

The software should be dimension-general and communication-group-general from the start.

The experiments will be enabled progressively.

================================================================================
3. SCIENTIFIC MOTIVATION
================================================================================

Biomedical information naturally exists across heterogeneous intrinsic dimensionalities.

Examples include:

1D:
- physiological signals;
- ECG;
- temporal waveforms.

2D:
- planar medical images;
- CFP/fundus photography;
- 2D slices.

3D:
- volumetric OCT;
- volumetric CT/MRI;
- 3D anatomical features.

4D:
- dynamic volumetric data;
- volumetric cine imaging;
- 3D + time representations.

Potentially higher-dimensional representations may also occur.

Conventional neural networks process such inputs in different native spaces.

Examples:

    1D feature:
    C1 x L

    2D feature:
    C2 x H x W

    3D feature:
    C3 x D x H x W

    4D feature:
    C4 x T x D x H x W

These tensors do not naturally possess a common spatial coordinate system.

Typical existing solutions therefore use:

- resizing;
- flattening;
- concatenation;
- learned projection;
- latent alignment;
- cross-attention;
- modality-specific fusion;
- task-specific fusion networks.

R&B investigates a different idea:

    Projection geometry itself can provide a common communication language.

The key conceptual shift is:

Radon/projective geometry is not used only for image reconstruction.

Instead, it is used as a temporary structured communication domain between heterogeneous neural representations.

================================================================================
4. CENTRAL R&B PRINCIPLE
================================================================================

R&B does NOT permanently convert all participating representations into the same native dimensionality.

Instead, every participating feature temporarily performs:

    Native Space
        ->
    Projection Space
        ->
    Communication
        ->
    Native Space

The backbone remains responsible for nonlinear representation learning.

R&B is responsible only for structured information exchange.

The complete conceptual sequence is:

    Project
        ->
    Reshape
        ->
    Handoff
        ->
    Interact
        ->
    Expand
        ->
    Backproject
        ->
    Residual Return

The default interaction inside R&B should remain linear.

This is deliberate.

The hypothesis to test is that a meaningful structured common geometry can enable useful cross-dimensional communication without requiring a highly expressive nonlinear fusion network inside the bridge.

Thus a full network may look like:

    nonlinear backbone
        ->
    linear R&B
        ->
    nonlinear backbone
        ->
    linear R&B
        ->
    nonlinear backbone

The overall model remains highly nonlinear even if R&B itself is simple and linear.

================================================================================
5. R&B PARTICIPANTS: NATIVE FEATURE NODES
================================================================================

An R&B participant is a neural feature node Fi.

A participant may originate from:

- any supported intrinsic dimensionality;
- any modality;
- any network;
- any network depth;
- any downstream task;
- the same or a different architecture;
- the same or a different medical system.

Participants do NOT need to have:

- the same number of channels;
- the same spatial size;
- the same dimensionality;
- the same network depth;
- the same architecture;
- the same task;
- the same output shape;
- the same prediction head.

The only fundamental requirement is:

    the node can be mapped through the corresponding generalized projection operator.

================================================================================
6. COMMUNICATION GROUPS
================================================================================

One R&B operation acts on a set of participating nodes:

    G = {F1, F2, ..., FK}

This set is called a communication group.

R&B is inherently multi-input and multi-output.

The participant identities before and after the interaction are the same:

    {F1, F2, ..., FK}
        ->
    {F1', F2', ..., FK'}

Each participant:

1. enters the common projection-domain interaction;
2. receives information influenced by the other participants;
3. returns to its own original network position.

Do NOT implement arbitrary routing where an output is written to a node that did not participate.

Rule:

    the same participants enter and leave the meeting;
    only their information has changed.

Cross-stage communication means that members of the same group may come from different relative depths in different networks.

It does NOT mean that one participant’s output is directly written into an unrelated nonparticipant node.

================================================================================
7. MULTI-STAGE DEPLOYMENT
================================================================================

The default conceptual deployment should support multiple sparse communication stages.

Avoid two extremes:

1. only one very-late R&B unit, which risks looking like ordinary late fusion;
2. fully dense all-to-all layer communication, which turns the paper into a topology-design study.

Preferred default:

    sparse multi-stage communication

For example:

Network A:
    A1 -> A2 -> A3 -> A4 -> A5

Network B:
    B1 -> B2 -> B3

Network C:
    C1 -> C2 -> C3 -> C4

Communication groups may be:

    G1 = {A2, B1, C2}
    G2 = {A3, B2, C3}
    G3 = {A5, B3, C4}

The exact number of R&B stages should later be determined experimentally.

A likely range for formal ablation:

    0, 1, 2, 3 R&B stages

The purpose is to test whether:

    communication
        ->
    native nonlinear processing
        ->
    communication again

is more useful than one-time fusion.

================================================================================
8. GENERALIZED ORIENTATION PARAMETERIZATION
================================================================================

For a d-dimensional native feature:

    Fd in R^(C x N1 x N2 x ... x Nd)

use:

    d - 1

angular variables:

    theta1, theta2, ..., theta(d-1)

Each angle uses the half-open interval:

    theta_j in [0, pi)

with:

- 0 included;
- pi excluded.

For Mj discrete positions:

    theta_j^(m) = m*pi/Mj
    m = 0, 1, ..., Mj - 1

The Cartesian product produces:

    N_orientation = product_j Mj

Examples:

2D:
    M1 orientations

3D:
    M1 x M2 orientation configurations

4D:
    M1 x M2 x M3 orientation configurations

The implementation must accept an arbitrary angle-sample sequence:

    [M1, M2, ..., M(d-1)]

Do NOT write unrelated hard-coded 2D, 3D and 4D implementations unless wrappers are needed for convenience.

================================================================================
9. GIVENS-BASED DIRECTION CONSTRUCTION
================================================================================

Each angular configuration determines an orientation through a sequence of Givens transformations.

Start from a fixed canonical basis direction e.

Apply a dimension-general sequence:

    e
      -> G1(theta1)e
      -> G2(theta2)G1(theta1)e
      -> ...
      -> n(theta)

The resulting:

    n(theta)

is the unit direction associated with the angular configuration.

The corresponding full orthogonal transform:

    Q(theta)

must also be available.

Important distinction:

    direction vector n
        is not the same thing as
    complete tensor transform Q.

The direction vector describes the projection orientation.

The full transform Q is needed when the tensor itself must be transformed/resampled and later returned through the inverse coordinate transformation.

The implementation must mathematically verify:

- Givens plane ordering;
- multiplication ordering;
- sign convention;
- determinant/orientation convention;
- canonical axis convention;
- normalization;
- numerical stability.

Do not proceed to large experiments until these conventions are unambiguous.

================================================================================
10. FIXED-AXIS PROJECTION PRINCIPLE
================================================================================

This is a central implementation concept.

For every projection orientation:

Do NOT implement a different summation operator.

Instead:

Step 1:
    use Q(theta) to transform/orient the tensor.

Step 2:
    always integrate/sum along the same canonical axis.

Therefore:

    orientation changes;
    projection axis remains fixed.

Intuitive interpretation:

    Move/rotate the object;
    keep the detector/summation direction fixed.

Conceptually:

    F
      -> Q(theta)
      -> oriented tensor
      -> fixed-axis sum/integration
      -> 1D projection signal

This should be the basis of a single dimension-general implementation.

================================================================================
11. SIGNED PROJECTION COORDINATE
================================================================================

Projection distance is represented using a signed coordinate:

    r in [-Rd, Rd]

The signed representation is important because of the hyperplane relation:

    (n, r) ~ (-n, -r)

The project must clearly document how:

    theta_j in [0, pi)

and signed r are used together.

Do NOT casually claim that all angle tuples produce globally unique directions.

At hyperspherical boundary configurations, especially zero-angle degeneracies, multiple angle tuples may represent the same direction.

The initial implementation may preserve the regular tensor-product angular grid even if a limited number of boundary configurations are redundant.

This is acceptable for the first implementation because the regular grid is:

- deterministic;
- easy to reproduce;
- easy to reshape;
- suitable for tensor processing.

A later efficiency optimization may remove duplicate directions if useful.

================================================================================
12. THE M–S–H REPRESENTATION
================================================================================

R&B uses three conceptually distinct representation structures.

These are not merely three arbitrary hyperparameters.

They are:

    M = Orientation Mesh
    S = Projection Span
    H = Communication Handoff

They correspond to different stages of the projection/communication process.

--------------------------------------------------------------------------------
12.1 M — ORIENTATION MESH
--------------------------------------------------------------------------------

The Orientation Mesh is:

    M1 x M2 x ... x M(d-1)

It represents the discrete orientation parameter space over:

    [0, pi)^(d-1)

It answers:

    From which orientations is this representation observed?

For 4D, for example:

    M1 x M2 x M3

forms a regular orientation mesh.

--------------------------------------------------------------------------------
12.2 S — PROJECTION SPAN
--------------------------------------------------------------------------------

The Projection Span is the discrete coordinate along the signed projection-distance axis:

    -Rd -> 0 -> +Rd

S represents how this complete signed projection support is discretized.

Changing S changes the number of discrete locations.

It should not, by default, crop the support.

S answers:

    How is each projected one-dimensional signal represented along signed distance?

--------------------------------------------------------------------------------
12.3 H — COMMUNICATION HANDOFF
--------------------------------------------------------------------------------

After projection, the representation contains:

- original backbone channels;
- orientation channels.

These are folded into a projection-channel dimension.

The compressed/subselected representation exposed to cross-network communication is called:

    Communication Handoff

H answers:

    How much projection-domain representation is handed off for communication?

================================================================================
13. R&B CONTROL VECTOR: UPSILON
================================================================================

Use Greek Upsilon.

Define the complete R&B control vector:

    Upsilon = (upsilon_M, upsilon_S, upsilon_H)

with:

    0 < upsilon_M <= 1
    0 < upsilon_S <= 1
    0 < upsilon_H <= 1

Notation:

- uppercase Upsilon denotes the full control vector;
- lowercase upsilon denotes an individual control coefficient.

The three coefficients independently control the M–S–H structures.

Full/reference setting:

    Upsilon = (1, 1, 1)

A lighter example:

    Upsilon = (0.5, 0.5, 0.25)

IMPORTANT:

Do not use upsilon = 0 as the formal way to disable R&B.
Use an explicit bridge-off configuration.

================================================================================
14. MESH CONTROL
================================================================================

Let:

    Mj^0

be the reference/full number of samples on angular axis j.

Then:

    Mj = max(1, round(upsilon_M * Mj^0))

Reducing upsilon_M must:

- preserve the angular domain [0, pi);
- reduce only the density/number of sampled orientations.

Do NOT interpret a lower upsilon_M as reducing [0, pi) to a smaller angular range.

Mesh control primarily affects:

- number of projections;
- projection compute;
- projection memory;
- downstream projection-channel count.

================================================================================
15. SPAN CONTROL
================================================================================

For participant i, define a reference/full-support projection resolution:

    Si^0

The exact formula should remain configurable until actual feature sizes and physical spacing are inspected.

Candidate default principle:

1. estimate the complete support needed for each participant;
2. use a diagonal/support-based reference;
3. define a group reference:

       S_G^0 = max_i Si^0

4. map every participant’s complete signed-distance range to a compatible common span;
5. apply upsilon_S:

       S_G = max(1, round(upsilon_S * S_G^0))

Reducing upsilon_S must:

- reduce the number of discrete samples;
- preserve the complete signed-distance support.

Do not describe the reference configuration as mathematically “lossless” unless formally established.

Preferred language:

- full-support reference;
- native-resolution reference;
- complete projection support.

Exact reconstruction properties depend on:

- angular sampling;
- distance sampling;
- interpolation;
- discrete transform implementation.

================================================================================
16. FORWARD RADON REPRESENTATION
================================================================================

After all orientation configurations and fixed-axis projection:

    Zd in R^(
        C
        x M1
        x M2
        x ...
        x M(d-1)
        x S
    )

Examples:

2D:
    C x M1 x S

3D:
    C x M1 x M2 x S

4D:
    C x M1 x M2 x M3 x S

Fold:

    C x M1 x ... x M(d-1)

into one projection-channel dimension:

    Pd = C * product_j Mj

Then:

    Zd
      ->
    Zbar_d in R^(Pd x S)

This is the canonical pre-Handoff representation.

Different participants may have different Pd.

They only require a compatible common S axis for direct interaction.

================================================================================
17. HANDOFF CONTROL
================================================================================

For participant i:

    Pi x S
      ->
    Hi x S

Define:

    Hi = max(1, round(upsilon_H * Pi))

Do NOT require:

    H1 = H2 = ... = HK

Different participants may preserve different absolute Handoff widths.

The shared control is the proportional factor:

    upsilon_H

This is preferred because a participant with originally small projection-channel count should not be compressed by the same absolute amount as one with a huge projection-channel count.

Default Handoff compression location:

    AFTER projection
    AFTER reshape
    BEFORE cross-participant interaction

Do NOT define Handoff as native channel compression before Radon.

Pre-Radon compression may later be evaluated only as:

- an implementation optimization;
- a memory-saving option;
- a controlled ablation.

================================================================================
18. PROJECTION-DOMAIN INTERACTION
================================================================================

For communication group:

    G = {1, 2, ..., K}

participants produce:

    H1 x S
    H2 x S
    ...
    HK x S

Concatenate along the Handoff/channel dimension:

    Z_G in R^((H1 + H2 + ... + HK) x S)

The default interaction operator should be:

    learnable linear 1D convolution/filter

The interaction must permit information from one participant to influence the returned representation of another participant.

Do NOT initially add:

- ReLU/GELU;
- attention;
- Transformer;
- nonlinear MLP;
- adaptive routing;
- learned gates;
- residual scaling gates.

These may be used only later as controls if scientifically needed.

The purpose of the first method is to test whether structured projection geometry plus lightweight linear interaction is sufficient.

================================================================================
19. RELATION TO FILTERED BACKPROJECTION
================================================================================

The method intentionally preserves the conceptual structure:

    Projection
      ->
    1D filtering
      ->
    Backprojection

This is one reason a 1D learnable convolution is natural.

However, distinguish two concepts:

1. analytical reconstruction filtering;
2. cross-representation learnable communication.

Do NOT claim that one universal classical reconstruction filter is mathematically identical across all dimensions unless proven.

Keep these components separable in code.

Possible later controls:

- no filter / identity interaction;
- fixed analytical filter where appropriate;
- learnable linear 1D filter;
- higher-capacity nonlinear mixer as an upper-capacity control.

================================================================================
20. EXPANSION AFTER INTERACTION
================================================================================

After interaction, split the mixed representation back according to participant identity:

    H1 x S
    H2 x S
    ...
    HK x S

For participant i:

    Hi x S
      ->
    Pi x S

using the participant-specific linear expansion corresponding to its Handoff compression.

Then reshape:

    Pi x S
      ->
    C
    x M1
    x ...
    x M(d-1)
    x S

This reconstructs the participant’s projection-domain tensor shape before backprojection.

================================================================================
21. BACKPROJECTION
================================================================================

For each orientation configuration:

1. take the processed 1D projection signal;
2. spread/backproject it along the same canonical projection axis;
3. apply the corresponding inverse coordinate transformation;
4. accumulate contributions from all orientations.

If Q(theta) is orthogonal:

    Q^-1 = Q^T

may be used according to the exact coordinate convention.

Important:

Backprojection/adjoint must not automatically be called an exact inverse.

Use careful terminology:

- forward projection;
- backprojection;
- adjoint;
- reconstruction/inversion only when mathematically justified.

The first R&B architecture requires a consistent return operator, not necessarily exact reconstruction.

================================================================================
22. RESIDUAL RETURN
================================================================================

For participant i, after backprojection obtain:

    Delta Fi

Return directly:

    Fi' = Fi + Delta Fi

Do NOT introduce gamma or another residual gate in the default design.

Rationale:

- residual return is simple;
- no extra non-core mechanism;
- avoids a new hyperparameter;
- preserves the focus on the R&B idea itself.

If training stability later clearly requires scaling, treat that as an engineering modification and evaluate separately.

================================================================================
23. DEFAULT COMPLETE R&B PIPELINE
================================================================================

For every participant:

    Native Feature
        ->
    Givens Orientation
        ->
    Fixed-Axis Projection
        ->
    M x S projection representation
        ->
    Fold native channels + Mesh channels
        ->
    P x S
        ->
    Handoff compression
        ->
    H x S

For one communication group:

    {H1 x S, H2 x S, ..., HK x S}
        ->
    concatenate
        ->
    learnable linear 1D projection-domain interaction
        ->
    split back by participant

For every participant:

    H x S
        ->
    expand to P x S
        ->
    restore Mesh dimensions
        ->
    fixed-axis backprojection
        ->
    inverse Givens transform
        ->
    Delta F
        ->
    F + Delta F
        ->
    continue original backbone

    prove architecture-agnostic and stage-agnostic communication.

Do not turn topology search into a separate research project.

--------------------------------------------------------------------------------
STAGE 12 — TASK-RELATION EXPANSION
--------------------------------------------------------------------------------

Do not use only the crude labels “same task” and “different task”.

Track independent axes:

A. medical target:
- same;
- related;
- different.

B. task family:
- classification;
- segmentation;
- regression.

C. output space:
- same;
- different.

D. head structure:
- shared head;
- separate heads.

E. branch sufficiency:
- strong standalone predictor;
- weak standalone predictor;
- auxiliary information source.

Representative scientifically distinct cases should progressively include:

1. same medical target + shared final output;
2. same medical target + separate predictors;
3. same semantic target + dimension-specific output spaces;
4. same task family + different targets;
5. different task families;
6. weak source assisting a strong predictor.

Do not execute the Cartesian product of all possibilities.
Choose cases because each adds a new scientific conclusion.

--------------------------------------------------------------------------------
STAGE 13 — DIMENSIONAL EXPANSION
--------------------------------------------------------------------------------

When early results are strong, progressively include:

- 1D;
- 2D;
- 3D;
- 4D.

The final target is not merely “the code accepts tensors of these dimensions”.

The target is:

    useful communication across these dimensions.

Validate:

- pairwise cross-dimensional communication;
- same-dimensional different-source communication;
- three-node communication;
- four-node communication;
- heterogeneous tasks.

--------------------------------------------------------------------------------
STAGE 14 — MULTI-NODE R&B
--------------------------------------------------------------------------------

After pairwise stability:

test true many-in/many-out communication.

Examples:

    1D + 2D + 3D
    1D + 2D + 3D + 4D

Compare:

- pairwise-only interactions;
- one multi-node communication group.

Question:

    Does the shared projection-domain interface scale naturally to multiple participants?

--------------------------------------------------------------------------------
STAGE 15 — TRAINING REGIMES
--------------------------------------------------------------------------------

Support at least:

A. Pretrained + frozen backbone
   Train only R&B.

Purpose:
   Is R&B itself extracting useful complementary information?

B. Pretrained + joint fine-tuning
   Likely main final performance setting.

C. End-to-end from scratch
   Tests whether R&B depends on pretraining.

Important:

Not every branch must be a strong standalone predictor.

A weak source may still provide useful complementary information.

Do not force meaningless standalone tasks merely to pretrain every branch.

--------------------------------------------------------------------------------
STAGE 16 — M–S–H ABLATION
--------------------------------------------------------------------------------

Use one or a small number of representative tasks.

Sweep separately:

    upsilon_M
    upsilon_S
    upsilon_H

Candidate values:

    1.0
    0.75
    0.5
    0.25

For each record:

- task performance;
- parameter count;
- FLOPs;
- runtime;
- peak memory.

Interpretation:

M:
    orientation budget

S:
    projection-span discretization budget

H:
    communication bandwidth

Do not run the full M x S x H Cartesian product unless later required.

--------------------------------------------------------------------------------
STAGE 17 — MIXER ABLATION
--------------------------------------------------------------------------------

Compare:

1. no learnable interaction;
2. fixed/analytical filtering where valid;
3. learnable linear 1D mixer;
4. optional nonlinear mixer as a higher-capacity control.

Question:

    Is simple linear interaction sufficient?

The nonlinear version should not automatically become the final method.

--------------------------------------------------------------------------------
STAGE 18 — PATIENT-SPECIFIC COMMUNICATION
--------------------------------------------------------------------------------

Only when earlier technical evidence is strong:

Use same-patient paired biomedical data.

Current expected future sources include:

- ECG;
- CFP;
- OCT;
- cardiac cine;
- additional user-provided sources.

Exact tasks are not yet fixed.

A critical control:

Correct pairing:
    Ai <-> Bi

Shuffled pairing:
    Ai <-> Bj, i != j

Question:

    Is R&B using patient-specific complementary information?

This control helps distinguish true subject-specific communication from:

- regularization;
- extra parameters;
- generic population-level correlations.

--------------------------------------------------------------------------------
STAGE 19 — CROSS-SYSTEM EYE–HEART STUDY
--------------------------------------------------------------------------------

If data/labels support it:

study communication between:

    ocular representations
        <->
    cardiovascular representations

Questions may include:

- Does eye information help heart tasks?
- Does heart information help eye tasks?
- Is benefit reciprocal?
- Which representations help which downstream tasks?

This stage is intended to elevate the study from:

    cross-dimensional neural communication

to:

    cross-system biomedical communication.

--------------------------------------------------------------------------------
STAGE 20 — SOURCE CONTRIBUTION ANALYSIS
--------------------------------------------------------------------------------

For multi-node R&B:

Use leave-one-source-out analysis.

For complete set:

    A + B + C + D

evaluate:

    -A
    -B
    -C
    -D

For every downstream task, record performance change.

Build a source-to-task contribution matrix.

Question:

    Who helps whom?

This is important for biomedical interpretation.

--------------------------------------------------------------------------------
STAGE 21 — EXISTING MULTIMODAL MODEL PLUG-IN
--------------------------------------------------------------------------------

Controlled experiments may use separated native encoders.

However, the final study should also test at least one realistic existing multimodal architecture that already contains fusion.

Compare:

    Existing multimodal model

vs.

    Existing multimodal model + R&B

Question:

    Is R&B only useful when we artificially separate branches,
    or can it improve an already fused system?

A positive result supports:

    plug-and-play communication module

rather than only:

    replacement fusion mechanism.

--------------------------------------------------------------------------------
STAGE 22 — ROBUSTNESS AND GENERALIZATION
--------------------------------------------------------------------------------

If the project remains on the NBE trajectory:

progressively add:

- multiple random seeds;
- confidence intervals;
- appropriate statistical tests;
- external validation;
- multi-center validation if available;
- domain shift analysis;
- missing-source robustness if scientifically relevant.

Do not add these before the core method is validated.

--------------------------------------------------------------------------------
STAGE 23 — NBE DECISION GATE
--------------------------------------------------------------------------------

The project should remain on the NBE trajectory if most of the following are true:

1. R&B consistently improves meaningful tasks.
2. R&B is stronger than generic learned projection/fusion controls.
3. Why-Radon evidence is convincing.
4. 1D/2D/3D/4D support is not only theoretical but experimentally useful.
5. Heterogeneous tasks and output spaces are supported.
6. Multi-node communication works.
7. Heterogeneous architectures work.
8. Same-patient pairing matters.
9. Cross-system experiments reveal meaningful complementary information.
10. External/generalization evidence is strong.
11. M–S–H provides interpretable efficiency-performance control.
12. The method remains conceptually simple.

If these conditions are not sufficiently met, narrow the claim.

Possible narrowed outcomes:

A. Strong 2D–3D method:
   target TMI / MedIA.

B. Strong medical multimodal method but limited dimensional generality:
   target TMI / MedIA.

C. Strong arbitrary-dimensional communication + biomedical insight:
   continue toward NBE.

29. WHAT NOT TO DO
================================================================================

Do NOT:

1. hard-code the entire method for 2D–3D only;
2. create separate unrelated implementations for every dimensionality;
3. force all participants to the same H width;
4. compress native backbone channels and call that Handoff;
5. crop angular range when reducing upsilon_M;
6. crop signed-distance support when reducing upsilon_S;
7. add residual gamma gates by default;
8. add attention/nonlinear MLPs before the linear version is tested;
9. perform exhaustive topology search;
10. require layer indices to match;
11. require every participant to solve a meaningful standalone task;
12. require every participant to have its own head;
13. assume same task means same output space;
14. assume same task family means same medical target;
15. claim exact inversion when only backprojection is used;
16. claim all angle tuples are globally unique when boundary degeneracy exists;
17. claim diagonal-based S is strictly lossless without proof;
18. claim dimension-agnostic behavior from only one 2D–3D experiment;
19. claim biomedical information transfer without subject-pair controls;
20. replace the MHD framework with an unrelated conventional implementation.

31. INITIAL SUCCESS CRITERIA
================================================================================

The first technical success is NOT an NBE result.

The first success is:

1. mathematically consistent generalized orientation generation;
2. working dimension-general projection;
3. correct M–S–H control;
4. correct multi-participant linear interaction;
5. correct backprojection;
6. stable residual return;
7. end-to-end gradient flow;
8. successful synthetic 1D–4D tests.

The first scientific success is:

    R&B improves a clean real paired task over no communication.

The first major scientific success is:

    R&B outperforms generic communication/projection controls.

The NBE-level success is:

    R&B behaves as a general, mathematically meaningful,
    patient-specific cross-dimensional biomedical communication framework
    across multiple dimensions, tasks, architectures and systems.

================================================================================
32. HIGH-LEVEL SCIENTIFIC EVIDENCE CHAIN
================================================================================

The final study should ideally build the following chain:

1. Projection geometry provides a structured common space.

2. R&B enables useful communication in a simple controlled cross-dimensional case.

3. The benefit is not explained by generic projection, random projection, simple concatenation or extra parameters.

4. The mechanism works across different task formulations:
   - classification;
   - segmentation;
   - regression;
   - same/different output spaces;
   - shared/separate heads.

5. The same principle scales across:
   - 1D;
   - 2D;
   - 3D;
   - 4D.

6. The method works across:
   - heterogeneous sources;
   - heterogeneous architectures;
   - different network depths;
   - cross-stage communication;
   - multi-node groups.

7. Same-patient pairing matters.

8. Cross-system communication reveals meaningful biomedical complementarity.

9. The M–S–H control vector provides interpretable performance/efficiency tradeoffs.

10. The method remains lightweight and conceptually simple.

================================================================================
33. FINAL PROJECT PHILOSOPHY
================================================================================

R&B should not become a complicated fusion architecture.

Its value should come from a simple principle:

    heterogeneous-dimensional representations
        ->
    generalized projection geometry
        ->
    common one-dimensional projection language
        ->
    lightweight linear interaction
        ->
    return to native space.

The mathematical interface should be general.

The bridge should be simple.

The experimental evidence should be broad and rigorous.

The project should expand only when earlier evidence justifies a larger claim.

The code should remain capable of supporting the maximum intended generality from the beginning, while the scientific story is progressively validated.
