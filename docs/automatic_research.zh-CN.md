# Radon_Bridge：独立完整研究流程

设计日期：2026-09-13；研究周期：2026_09_10_11_11_31。

当前状态：**流程设计已形成；大队列项目执行链尚未接通，不能标为已部署自动研究。**
本文件规定实施顺序、准入证据和科研边界。它不启动训练、不解封test，
不替换健康的基础模型任务。旧小队列的结果保留为探索依据，不能冒充本轮结果。

## 1. 研究对象和与LOOK的区别

输入是同一参与者、同一访视且眼别对应的CFP二维影像与OCT三维体积。
分别使用完整独立训练的MHD模型，包括各自任务头。桥连接模型内部原节点，
结果仍写回原Node ID；两条任务头都保留。

- 训练损失：CE_CFP + CE_OCT；本轮参考配方采用未加权CE，类别比例和各类召回同时报告。
- 共同检查点、平台和调度主指标：(CFP macro-F1 + OCT macro-F1)/2。
- 分别报告CFP、OCT，明确桥接后的分支预测可以依赖另一模态。
- 固定概率平均仅为次要输出，不把其F1当成分支F1平均值。
- 不恢复已撤销的末端可学习融合头/融合损失协议；不套用LOOK汇合后单主干的宿主构造。
- 先研究同一疾病的两模态协作；跨疾病多网络组合另立轮次，不能从本轮自动推出。

## 2. 库存持续更新，科研轮次固定

基础模型库存由Model_Training维护，MHD_Framework只提供通用架构。
Radon_Bridge持有父模型副本、桥、微调结果及研究报告，不回写共享权重。

持续发现模型不等于持续改变同一项实验的父模型。每轮生成不可变catalog，
按疾病、模态维度、架构和原生训练制度分组，记录全部候选及候选资格。
探索pilot和已标注不能正式选型的模型不能自动升级为正式父模型。

组内候选全部达到已声明的结束标准并验收后，在seed3416上按开发集macro-F1
提名；同分依次按AUROC和固定配置指纹排序。模型分数不设跨疾病统一门槛。
基础设施失败进入需处理；正常低分仍保留，不能删除以促成提名。
两种模态独立选配方，再按原配方补3417/3418，不重新搜索。后两个种子单独报告。
出现新候选进入下一轮，不改本轮父模型、不因项目早期结果倒换父模型。

## 3. 必须完成的八个阶段

| 阶段 | 自动动作 | 放行证据/失败处理 |
|---|---|---|
| 数据准入 | 核对标签时间、划分、访视/眼别、2D/3D预处理和缓存 | train/development清单SHA、人数及重放；test无授权不访问 |
| 原生候选验收 | 验收配置、初始化、完成标准、权重、框架与环境 | 不能用文件存在、状态字符串或未结束的最高分替代验收 |
| 提名和重复 | 固定提名，登记两个重复种子，精确复用已有配置 | 三种子、两模态齐全；不同眼可用性/预处理必须明确匹配 |
| 父模型接入 | 复制完整模型并严格加载；重放完整开发预测 | 状态/预测/参与者顺序/Node ID验收，输入梯度和首次更新验证 |
| 桥基与资源 | 仅train拟合SVD；逐结构进行完整任务峰值和恢复测试 | 基来源SHA、形状/普通返回/零初始化、优化器/BN/RNG恢复及显存准入 |
| 项目训练 | 登记不可变实验单元，匹配父模型、顺序和训练配方 | 对照不得因结果较差跳过；达到保护上限不当作完成 |
| 开发评价与诊断 | 重放选中模型，配对比较、方向关闭、统计与报告 | 原始结果、比较族、异常与不确定性均保留，不据此追加同轮搜索 |
| 锁定与test | 锁全部模型、比较及权重，审计数据使用记录后统一评价 | test只推理；任何污染/未知用途阻止解封，不能改epoch/阈值/配置 |

缺少3D父模型时状态是waiting_3d_parent。二维OCT切片不能替代三维父模型；
维度、网络实现和预训练来源都要分别记录。部分阶段可准备，但不能先伪造正式项目结果。

## 4. 第一批参考比较：小而完整

先把ResNet50二维CFP + ResNet50三维OCT这一组接通，覆盖青光眼、白内障、
黄斑变性三个既有任务与3416–3418三种子。三维版本的实际实现/初始化须由catalog
明确，不能把2D ImageNet权重称为直接3D预训练。

| 实验臂 | 回答的问题 |
|---|---|
| 无通信继续训练 | 单纯继续优化能获得多少收益 |
| 固定非中心化SVD + Radon_Bridge | 结构化双向通信的整体增益 |
| 同基同宽普通线性重采样 | Radon几何相对普通线性通信的额外收益 |
| 同基仅自身处理 | 增益是否需要跨来源项 |
| 单stage MMTM，共享隐层256 | 与常用非线性通道调制直接比较 |
| 单stage双向交叉注意力，d256、4头 | 与常用非线性空间通信直接比较 |

六臂 × 三任务 × 三种子 = **54个第二阶段训练位置**，原父模型是额外只读参照。
这是设计位置数，不是已登记/已开跑任务数；准确复用和可行性锁定后再形成队列。

参考桥固定stage3、M32、S64、k3；两路目标实际通道秩r=32、h=rM=1024。
各来源rho=r/C按实测C派生并记录：不能把ResNet18的rho=1/8直接套到ResNet50，
然后宣称通信宽度不变。C不足32或该架构无对应stage时拒绝隐式适配，另立映射。
普通通信复用同基、同宽、k和前向/返回行范数规范。MMTM/注意力不假称等参数。

参考微调配方继承已用的AdamW、backbone LR=6e-5、head/bridge LR=1e-4、WD=0.01、
有效batch16、FP32、各分支/通信模块分别裁剪5、全参数训练和BN正常更新。
至少8轮、连续6轮未超过0.001改善判平台、3轮停滞LR×0.3、60轮保护上限。
microbatch/累积在读取新项目分数前按整套模型资源预检固定，所有匹配臂相同；
若预检不能支持当前约定，记录不可行或新配方偏离，不能在运行中偷偷缩小batch。
原生预训练仍保留其各自文献/探索训练制度，不被此项目配方改写。

## 5. 扩展以研究问题组织，不再全量扫描参数

下面是后续轮次模板；每轮必须在读取其新结果前锁定配置、精确数量及比较清单，
不因主方法输赢选择要运行的对照。第一批完成并非后续全部完成。

| 研究问题 | 成组补充设计 | 解释边界 |
|---|---|---|
| 不依赖SVD吗 | QR-Radon与QR普通通信一起补，与SVD几何增益作交互 | 不是只比两个最佳压缩分数 |
| 空间与S邻接真的有用吗 | 同基空间打乱、固定S轴置换及逆置换；复用标准臂 | 固定预算，不能把打乱后的顺序称为物理角度 |
| 两个方向各自贡献 | 保留自身项的两单向训练 + 只读关闭/配对打乱 | 删除依赖和重新训练增益分别解释 |
| 是否依赖原网络共同适应 | 冻结主干、头、BN的Radon/普通/自身完整匹配组 | 只训练桥；验证冻结SHA，不把卷积梯度正交推广到全网 |
| 能迁移到其他骨干吗 | 第二/第三个预定2D/3D架构对，重复六个主臂 | 架构自身强弱和桥增益分开；不得用2D父模型凑3D对照 |
| 能增强已有非线性宿主吗 | 宿主继续训练/宿主+Radon/宿主+普通通信 | 保留双头，写回前特征并行残差；从宿主train特征重新拟合同一套基 |
| 宽度、方向和多桥是否稳健 | 沿用小队列预先确定的代表设置，做成组有限复核 | 不复制数千格搜索；层位置、r/M/h与总预算同时记录 |

第二/第三架构对先查现有正式资格和真正3D实现，再在性能筛选前登记名称与stage映射。
模型尚未就绪不等于需要重新搜索桥超参数。暂不增加疾病/标签或改原始数据划分。

## 7. 真实执行和状态语义

建议实现：studies/autoresearch.py管理catalog和轮次；models/native_materialization.py
管理原生训练实际格式；training/project_runner.py执行双分支实验；
runtime/project_dispatch.py仅发布到统一原子领取/资源准入机制。
名称是实施分工，不代表文件已存在。

状态依次为 discovered、waiting_native_screen、waiting_replications、
waiting_replay、waiting_resource_acceptance、ready、running、
acceptance_pending、accepted、development_report_ready、waiting_test_gate、closed。
failed_needs_review与paused_resumable单列；一个组受阻不影响其他组。

基础模型源由其owner掌管，项目使用独立副本。缺少模型发请求而不静默随机初始化。
重启先核实旧step退出，沿用原run、配置和完整断点；定时检查不负责抢占/实时准入。
保留健康任务，新增完整任务峰值通过后才安全切换；不能为维持占卡伪造训练。
GPU时长不是训练完成标准。按现行整卡预算保留约10GiB、主机内存至少15%余量。
