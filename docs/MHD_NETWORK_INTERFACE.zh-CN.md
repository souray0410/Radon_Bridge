# 原生网络、通信接入与 MHD 执行的职责

## 三层边界

1. `native_networks.build_cfp_oct` 构建当前两个完整原生网络：输入、可见中间节点、任务头、损失，以及协议要求的融合头。这里不接 R&B。
2. `integration.attach_communications` 只处理指定特征节点的通信接入与形状检查。R&B、MMTM、交叉注意力以及并行残差均在此层接入，保持原 Node ID。
3. `mhd_task.MHDTaskGraph` 编译并调用已有 MHD V4 的前向、反向和检查点操作。它不实现第二套自动微分，也不假定 CFP、OCT、ResNet、双眼或 stage3。

当前 `model.PilotGraph` 保留旧函数签名，委托给这三层；旧模块名、节点编号、构建顺序和检查点字典不因文件拆分而改变。

## 替换网络时的接口

新的网络构建函数返回 `NativeNetwork`：

通信特征必须明确采用 `[batch, channels, *spatial]` 布局，且批次内的对应关系已经建立。Token 序列等其他布局需要显式的可逆视图转换，接口不会把同一形状自动解释为相同的解剖或语义坐标。一维输入的当前无向几何只有一个方向（M=1）。

- 已有 `MHDBuilder`，保留各层原生节点与边，不能把整网藏在一个不透明的边中。
- 输入节点名和对应形状探针；输出名称到预测节点的映射；标量总损失节点。
- 来源名称、各来源检查点模块集合，以及完整原生检查点模块集合。
- 可选损失缩放边和描述性元数据。分支／融合损失在原生任务定义中明确构建，不由桥猜测。

随后使用 `MHDTaskGraph(native_definition, bridge_configs=..., device=...)`，通过 `forward_inputs({输入名: 张量})` 和 `backward()` 执行。桥配置通过稳定的中间节点名指定接入位置；形状由原生图的只读探针得到。

网络接口支持导入另一个显式搭建的 MHD 图，不等于能够无条件导入任意序列模型、任意检查点或现成编译图。外部模型需要声明输入／输出／损失／特征接口，不自动猜测通道排列或样本配对。

## 科学与实现边界

- 本次没有替换正在研究的 ResNet18，没有引入新的数据或实验臂；结构拆分必须通过旧版输出、梯度、参数、节点及严格加载等价测试。
- 当前 UKB 数据加载器、双眼约定、ResNet 优化器的四 stage 策略、能量诊断和训练选优规则仍属于当前实验适配器。未来导入别的模型时，必须一并明确参数分组、配对、特征形状和评价协议；不能仅替换模型后就声称已完成公平对比。
- R&B 的线性、固定基和残差初始化等数值性质可以独立检验；新模型上的性能与稳定性须重新验证，不能由接口兼容推得。
- `native_forward_inputs` 是同一图的 PyTorch 参考执行，用于对照 MHD 数值结果，不是另一种训练算法。
