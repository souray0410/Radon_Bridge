# 项目预留与基础模型让位

本次只升级工作管理入口，不改变Radon_Bridge科学协议、模型结构或既有训练源码。项目预留与基础模型补卡上限由共享的`research_gpu_roles_v1`策略分别控制；运行和待批均计数，历史交接账本按Slurm作业ID去重。

新allocation owner可对待执行项目做有时限的共存资源预检：保留健康基础模型，预估整卡余量，再完成独立前后向、优化器更新及断点恢复。通过后只请求该基础模型保存并暂停；旧step退出后其原run ID回候选池，项目优先领取。资源不足或预检失败不先停旧任务。正式项目各实验臂仍必须通过各自完整预检。

`control_source`只提供额外调度模块，原科学依赖保持原路径。`legacy_project_pythonpath`让既有项目worker执行其原科学快照。CPU管理器以standby启动，校验源码与候选，再接受共享账号锁下的交接账本；有活跃salloc子进程的旧CPU会话保持存活至子进程退出。旧GPU owner不热修改，随正常allocation轮换使用新版。
