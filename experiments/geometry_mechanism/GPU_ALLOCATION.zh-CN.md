# 任意指定GPU的运行时调度

用户明确要求单卡、双卡及多卡均可指定，当前继续使用物理GPU 0、1。GPU选择属于运行安排，不改变实验配置指纹、batch16、梯度、优化器、种子或平台标准。每项实验仍由一张卡独立训练。

运行配置保存在 `/data/mengh/RadonBridge/gpu_allocation.json`，服务通过 `RB_GPU_ALLOCATION_FILE` 显式指定并要求该文件存在。使用生产检出的环境执行：

```
python -m scripts.set_gpu_allocation --show
python -m scripts.set_gpu_allocation --gpus 1
python -m scripts.set_gpu_allocation --gpus 0 1
python -m scripts.set_gpu_allocation --gpus 0 2 5
python -m scripts.set_gpu_allocation --gpus
```

编号为当前设备清单中的物理GPU编号，记录对应UUID。示例不表示ws02实际有六张卡。去掉卡后，该卡当前任务正常结束，不再领新任务；加入空闲卡后可继续领任务。空列表暂停新增派发，保留活跃任务。改变列表无需重启队列，也不自动重新训练已接受结果。不会即时迁移正在运行的模型；紧急中断需单独处理并保留attempt。

列表原子写入；未知卡、重复编号、负数、非法文件及必需配置文件丢失都会暂停新派发，不自动回退双卡。每次变化记录配置SHA、时间、当前任务和设备。监控必须保留用户最新选择，包括空列表；不得把有意暂停误作失败重启。

显存限制是每张物理GPU上本项目所有可识别R&B工作进程显存之和不超过10 GiB，不是所有GPU合计，也不包括LOOK等其他项目。除本控制器子进程外，以 `python -m radonbridge.*` 标识额外项目worker。自行用其他入口运行的进程应接入该标识，不能认为任意未标识进程都会被自动识别。每张卡最多派一个本队列任务；若已有其他R&B worker则等待。其他项目显存只影响设备实际可用空间检查；保留原派发空闲显存门槛，不停止LOOK。

支持任意长度设备列表，训练并发随选定可用卡数扩展；归档积压门槛仍为4，派发前额外检查随活跃任务数增长的磁盘峰值需求。源码更新使用新不可变检出，旧队列正常排空后衔接；保存旧协议和候选锁，限定只允许经过验证的调度代码更改。

验收：模拟六卡覆盖单/双/多卡、暂停恢复、去卡完成当前任务、20项恰好执行一次；验证LOOK显存不计入本项目上限、额外R&B worker计入；原单卡/双卡与滚动调度故障测试通过。多于两卡属于模拟调度验收，ws02实际运行验收使用当前两卡。
