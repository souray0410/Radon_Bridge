# 研究报告的一般原则：让读者能够独立判断

本准则适用于所有项目的累计页面、周报、图表、论文草稿及进度答复。负责人主动执行，不以用户补充提醒作为验收环节。具体术语和配方在项目中维护；不把一次修改积累成互不相干的特例。

## 核心判断标准

读者无需参加此前讨论，也应能独立回答：为什么做、怎样比较、观察到什么、证据支持到哪里、下一步为什么值得做。信息是否足够取决于读者能否正确判断，而不是是否填满模板、写够页数或罗列足够配置。

1. **问题驱动。** 以科学问题和可被否定的主张组织叙述；算法、机器和配置服务于问题。先回答老师已提出的问题，再明确补充机制的作用。理论已决定的结论无需用重复实验装饰。
2. **比较可辨识。** 交代比较对象、改变因素、固定条件、合法差异和替代解释。用匹配组回答问题；参数量、初始化、选模预算或输入不同不能藏在简称后。范围完整不等于所有组合必须当下穷举。
3. **证据与结论对应。** 给出基线、差值、样本量、随机种子、数据角色、统计不确定性、反例和失败。区分计划、实现、运行、验收；区分探索、复现、内部调参表现和独立评估。不能用单种子选优或区间跨零宣称稳定优越或等效。
4. **读者自足。** 名词首次解释；符号说明对象、维度和单位；表头和图注能独立解释比较方向与指标。层级安排为结论/问题→关键证据→实现与溯源附件。精确不等于堆术语，通俗不等于隐藏数学条件。
5. **完整且可追溯。** 所有批准问题有状态和去向，负结果与未完成项可见。结果对应稳定配置、实际算法及源产物，累计页不丢旧证据，不混不同队列；改动记录原因和生效时间，历史报告保持原快照。
6. **行动由证据推动。** 结果之后解释它排除了什么、还有什么竞争解释，以及下一项最小有信息量的比较。承认证据不足，避免为了凑数量扩大矩阵；技术问题先闭环修复再解释科学结果。

## 与公开报告指南的关系

参考[CLAIM 2024，Radiology: Artificial Intelligence](https://pubs.rsna.org/doi/10.1148/ryai.240300)：明确研究目标、数据与预处理、模型/评估方法及透明复现；指南允许说明不适用项，它不是科学质量打分器。临床预测模型开发或评价可再按适用性参考[TRIPOD+AI 2024，BMJ](https://www.bmj.com/content/385/bmj-2023-078378)。这里是项目执行原则的综合整理，不是全文复制或已完成逐项合规认证；不能声称TMI/MIA/NBE均强制同一清单。正式投稿时重新核对目标期刊当前作者指南，并记录适用/不适用及证据位置。

本项目dev仍实际用于选择时，报告明确称“开发/调参集”，不能只换成“独立测试”用语来制造验证；现有test封存政策不因报告指南改变。算法机制研究也不能仅凭报告完整就声称临床有效。

## 发布前由负责人自查

- 脱离聊天上下文，陌生读者是否能说出本页主问题、比较对象和证据界限？若不能，改结构而不是只补括号。
- 每个结论能否回指具体数据/公式和比较？是否遗漏反例、失败、未完成情况或不公平差异？
- 图、表、标题、正文是否使用相同术语、单位、配置与截止时间？是否把仅实现/预检写成结果？
- 当前实验顺序是否继续回答最重要未知问题？旧证据能否复用，下一项是否可能改变解释？

机械门槛负责身份、缺行、重复、数值、链接和生成一致性；负责人另做上述语义审查。任何一项未知就标记并解决，不因CI通过而免除判断。每次发布保存简短“问题—证据—反例—限制—下一动作”记录；不用伪造已完成的自动理解能力。修改展示应同步生成器，避免下次汇总回退。

[统一术语与命名规范](NAMING_STANDARD.md)要求从生成器到当前产物一致核验，已知错误由发布检查拦截。
